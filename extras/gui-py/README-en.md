## 1. Project Overview & Architectural Philosophy

### Application Purpose
The **`gui-py`** module is an optional, lightweight, high-performance web user interface designed to extend the core script **`bash4llm`** (v2.8.5+). Its primary purpose is to provide a modern graphical user experience (WebUI Single Page Application) accessible from any web browser, while preserving the deterministic, Bash-first nature of the underlying infrastructure.

### Key Architectural Principles

1. ***Thin Adapter* Model**:
   * The core script `bash4llm` remains the single source of truth for domain logic, NDJSON conversation thread state, filesystem persistence, Vault encryption, provider selection, and direct API calls to LLMs.
   * The Python Adapter implements no domain storage of its own, does not alter file formats, and does not duplicate business logic.
   * The presence or absence of the `gui-py` module (or Python dependencies such as `fastapi`, `uvicorn`, `pydantic`) **does not modify or compromise the operation of the core script `bash4llm` in any way**.

2. ***Domain-Stateless / Runtime-Stateful***:
   * **Domain-Stateless**: The Python Adapter does not permanently store messages, API keys, or history. Thread reading occurs via read-only extraction from the `.ndjson` files generated by the core.
   * **Runtime-Stateful**: The Adapter manages in ephemeral RAM memory an active job registry (`jobs_registry`), subprocess handles (`process_pid`), Server-Sent Events token queues (`job_queues`), active client sessions (`sessions`), and a temporary idempotency table (`idempotency_store`).

3. ***Zero Credential Mirroring***:
   * Python does not store, extract, or manipulate LLM credentials or the Vault master password in plaintext on disk.
   * Provider authentication is delegated entirely to the core `bash4llm` via isolated process environment variables or through the Bash script's native in-RAM Vault mechanism (`_B4L_RT_CTX`).

4. ***No Double Locking***:
   * The Python Adapter does not apply mutexes or synchronization locks on domain files. If two or more requests target the same `thread_id` simultaneously, Python allocates and runs their respective asynchronous subprocesses, delegating transactional filesystem arbitration to the native atomic locking mechanism of `bash4llm` (`acquire_thread_lock`).

### Installation and Synchronization
All module source files reside in the `extras/gui-py/` directory of the repository. Local system installation is performed via the core CLI:

```bash
./bash4llm --install-extras
```

This command copies the tree into `bash4llm.d/extras/gui-py/` enforcing restrictive permissions of `0700` for directories and `0600` for files (`0700` for `gui-py.sh`).

### 🚀 Quickstart Application Launch

Launching the WebApp GUI is done directly via the `bash4llm` CLI:

```bash
./bash4llm --gui
# or
./bash4llm --webapp
```

The core script verifies module cryptographic integrity via `manifest.sha256` and delegates execution to the wrapper script `extras/gui-py/gui-py.sh`.

#### 💻 Platform-by-Platform Execution

* **Linux / macOS**:
  ```bash
  ./bash4llm --gui
  ```
  The wrapper script sanitizes the environment, validates the presence of Python >= 3.10 and required modules, acquires the kernel Advisory Lock on `gui_adapter.lock` via `fcntl.flock`, and allocates the first available loopback port (starting from `19970`). A dedicated background worker (`_launch_browser_async`) performs a TCP socket readiness check and executes the native platform dispatcher (`xdg-open` on Linux or `open` on macOS) with POSIX session isolation. Automatic browser launch can be disabled by setting `BASH4LLM_GUI_NO_BROWSER=1`.

* **Windows (Git Bash / MSYS2 / WSL)**:
  ```bash
  ./bash4llm --gui
  ```
  In WSL environments, `wslview` or PowerShell interop (`Start-Process`) is utilized. Under native Windows, the lock is managed via `msvcrt.locking` with 1-byte initialization and browser launching is delegated to `cygstart` or PowerShell.

* **Android (Termux)**:
  ```bash
  ./bash4llm --gui
  ```
  Detects the Termux environment (`IS_TERMUX` / `BASH4LLM_PLAT_ANDROID`) and executes `termux-open-url` to dispatch the Android browser Intent. It concurrently prints the full authentication URL to the terminal as a manual fallback.

### 🌐 GUI WebApp User Manual

1. **Initial Authentication (One-Time Token & Direct Handshake)**:
   At startup, a cryptographic 64-hex character `one_time_token` is generated. The browser is directed to:
   `http://127.0.0.1:19970/auth?one_time_token=...`
   The token is consumed atomically in RAM upon first access, and the server directly renders `index.html` (`200 OK`) while setting a secure `HttpOnly` host-only session cookie with the `SameSite=Strict` flag. Upon initial load, the client JavaScript runs `window.history.replaceState({}, document.title, "/")` to clean the URL bar.

2. **Thread Navigation (Left Sidebar)**:
   * **+ New Thread**: Initializes a new multi-turn conversation context.
   * **Thread List**: Displays active conversations. Clicking on a thread loads the message history in read-only mode from `.ndjson` files.
   * **🗑️ Delete**: Permanently deletes the selected thread or clears default chat history.
   * **Rename**: Allows renaming the thread title (updated via `PATCH /api/threads/{id}`).
   * **📊 Stats**: Displays message count, session segments, and cumulative byte usage (`GET /api/threads/{id}/snapshot`).

3. **Prompt Submission and Real-Time Streaming**:
   * Type the request into the bottom input area and press **"Send"** (or `Enter`).
   * The LLM response streams in real time token-by-token via Server-Sent Events (SSE).
   * **Stream Toggle**: Allows disabling streaming to receive the complete response in a single block.

4. **Immediate Interruption (Stop Button)**:
   During generation, the send button turns into **"Stop"**. Clicking it forwards a `POST /api/jobs/{id}/cancel` request, halting the subprocess with an immediate termination signal (`SIGTERM`/`SIGKILL` on POSIX or `taskkill` on Windows), without corrupting prior history.

5. **Context Attachments (📎 Attach)**:
   Allows uploading one or more text/context files. The backend saves the file into `$BASH4LLM_TMPDIR/gui_uploads/` with `0600` permissions and forwards it to the core `bash4llm` via the `-f` parameter.

6. **Prompt Templates (Templates)**:
   Allows selecting and applying one of the text templates stored in the project's `templates/` directory.

7. **SML Gate (Safety Validation)**:
   Enforces mandatory semantic validation of the Structured Metadata Layout schema (presence of `LISTEN_SUMMARY` and `CONVERSATION_OUTCOME` blocks). If the model fails the schema, the response is flagged as unverified.

8. **Output Sanitization (Sanitize)**:
   Automatically strips ANSI terminal color escape sequences and non-printable control characters from the response stream.

9. **OpenSSL Key Vault Management (🔒 Vault)**:
   Opens the modal dialog to manage API keys encrypted with local AES-256 encryption:
   * **Unlock Vault**: Authenticates with Master Password in RAM memory (`_B4L_RT_CTX`).
   * **Save Keys**: Securely stores new API keys for each supported provider.

10. **Settings Panel (⚙️ Settings)**:
    * **Provider & Model**: Select active LLM backend and inference model.
    * **Set Default**: Saves preferred model for the active provider (`POST /api/models/default`).
    * **🔄 Refresh Models**: Queries the provider API to resynchronize the model catalog (`POST /api/models/refresh`).
    * **Generation Parameters**: Adjust System Prompt, Temperature (0.0 - 2.0), and Max Tokens (1 - 128000).
    * **Context Strategy**: Choose between message count window (`thread_window`, 0-100) or byte-budget limit (`target_bytes`).

11. **Clean Server Shutdown (🛑 Stop Server)**:
    Sends a `POST /api/shutdown` request, cleanly halting the Python backend process.

### Job Lifecycle (`JobState`)

Each generation request submitted to the WebApp is encapsulated in a `Job` object managed in RAM memory by the Python Adapter.

```text
       [ Client POST /api/chat ]
                   │
                   ▼
             ┌─────────┐
             │  CREATED  │ (Allocated in memory registry)
             └────┬────┘
                   │
                   ▼
            ┌──────────┐
            │  STARTING  │ (Asyncio subprocess invocation)
            └─────┬────┘
                   │
                   ▼
             ┌─────────┐
             │  RUNNING  │ (Prompt injection via stdin pipe)
             └────┬────┘
                   │
                   ▼
             ┌───────────┐
             │  STREAMING  │ (Token streaming via SSE)
             └─────┬─────┘
                    │
     ┌────────────┼────────────────────────┐
     │              │                            │
     ▼             ▼                            ▼
┌───────────┐ ┌──────────┐         ┌──────────────────┐
│  COMPLETED  │ │  FAILED    │         │  CANCEL_REQUESTED   │
└───────────┘ └──────────┘         └────────┬─────────┘
(Exit Code 0)   (Exit Code != 0                   │
                 or JSON error)       ┌─────────┴─────────┐
                                      │    Process Killed    │
                                      └────────┬──────────┘
                                                │
                                                ▼
                                         ┌───────────┐
                                         │  CANCELLED  │
                                         └───────────┘
```

#### Formal State Descriptions (`JobState` Enum)
* **`CREATED`**: The Job has been allocated in the idempotency registry `jobs_registry` with a unique `job_id` (`job_<hex16>`).
* **`STARTING`**: The Adapter has prepared the explicit CLI argument list and sanitized environment, and is launching the subprocess via `asyncio.create_subprocess_exec`.
* **`RUNNING`**: The `bash4llm` process is active (`process.pid` assigned). The user prompt is transmitted via asynchronous write to the `stdin` pipe.
* **`STREAMING`**: Tokens generated by `bash4llm` are read from `stdout` via `codecs.getincrementaldecoder('utf-8')` and streamed to the client via SSE.
* **`CANCEL_REQUESTED`**: A `POST /api/jobs/{job_id}/cancel` request was received. The Adapter initiated the process tree termination procedure.
* **`CANCELLED`**: The `bash4llm` process was successfully terminated by a system signal (`SIGTERM` or `SIGKILL`). The `termination_cause` field is populated.
* **`COMPLETED`**: The `bash4llm` process exited cleanly with exit code `0`. The full response is stored in the RAM buffer `prompt_response`.
* **`FAILED`**: The process exited with a non-zero exit code or the core emitted a JSON diagnostic error on `stderr` (`core_error_code` $10\div17$).

### Multi-Tab Management, Active Clients & RAM Memory

The Adapter handles the concurrent presence of multiple browser tabs or clients through dynamic session tracking.

#### Formal Definition of *Active Client*
A client is considered **Active** if at least one of the following conditions is met:
1. It has an open, listening HTTP Server-Sent Events stream (`/api/stream/{job_id}`).
2. It performed an HTTP interaction or sent a Heartbeat signal (`POST /api/heartbeat`) within the activity window of **1800.0 seconds** (`sessions[session_id] >= now - 1800.0`).

#### Automatic Graceful Shutdown Algorithm
To prevent the Python server from running indefinitely in the background when the browser is closed, the Adapter runs a permanent asynchronous background task (`graceful_shutdown_checker`).

The server automatically terminates by sending a `SIGINT` signal to itself if and only if the following logical-temporal equation is satisfied:

```math
\text{server\_has\_seen\_first\_client} == \text{True} \quad \land \quad \text{Active Clients} == 0 \quad \land \quad \text{Active Jobs} == 0 \quad \land \quad (\text{now} - \text{grace\_started\_at}) \ge 1800.0\text{s}
```

#### RAM Memory Garbage Collection
The `prune_expired_memory_records()` function runs periodically to prevent unbounded RAM growth:
* Completed jobs older than 2 hours ($TTL = 7200.0\text{s}$) are evicted from memory.
* If the registry exceeds 200 total records, the oldest inactive jobs are forcibly evicted while protecting currently running jobs.

### Subprocess Management and Cross-Platform Cleanup

Job cancellation (`cancel_job_process`) is a deterministic process termination and **not a transactional rollback**. If the core already committed an NDJSON line before signal reception, that line remains persisted in the domain.

#### Process Tree Termination Algorithm
1. **POSIX Platforms (Linux, macOS, WSL, Termux)**:
   * The Adapter sends `signal.SIGTERM` to the subprocess PID (`os.kill(job.process_pid, signal.SIGTERM)`).
   * The Adapter sets `job.termination_cause = TerminationCause.SIGTERM` and awaits in a non-blocking loop up to a maximum of $5.0$ seconds (50 iterations of 100ms).
   * If the process does not terminate within $5.0$ seconds, the Adapter forces termination by sending `signal.SIGKILL` and updates `job.termination_cause = TerminationCause.SIGKILL`.

2. **Windows Platforms (Git Bash / MSYS2)**:
   * The Adapter asynchronously executes the native system utility:
     ```cmd
     taskkill /F /T /PID <process_pid>
     ```
   * This guarantees forced recursive termination of the entire child process tree spawned by the Bash shell.

## 4. IPC Protocol and Data Streaming (IPC Contract)

### Asynchronous CLI Invocation and Prompt Injection
The Python Adapter invokes the core script `bash4llm`, dynamically assembling command-line parameters:

```python
cmd = [
    "bash", core_script_path,
    "--thread", safe_thread_id,
    "--thread-window", str(job.thread_window),
    "--json-diagnostics"
]

if job.stream:
    cmd.append("--stream")
if job.provider:
    cmd.extend(["--provider", job.provider])
if job.model and job.model.lower() != "default":
    cmd.extend(["--model", job.model])
if job.system_prompt:
    cmd.extend(["--system", job.system_prompt])
if job.temperature is not None:
    cmd.extend(["--temperature", str(job.temperature)])
if job.max_tokens is not None:
    cmd.extend(["--max", str(job.max_tokens)])
if job.template:
    cmd.extend(["--template", job.template])
if job.validate_sml:
    cmd.append("--validate-sml")
if job.sanitize_output:
    cmd.append("--sanitize")
if job.attachments:
    for att_path in job.attachments:
        if os.path.isfile(att_path) and os.access(att_path, os.R_OK):
            cmd.extend(["-f", att_path])
```

#### Passing Prompt via `stdin` Pipe
To mitigate security risks associated with process list inspection by other system users (`ps aux`) and overcome CLI argument length constraints (`ARG_MAX`), user prompts are injected strictly through the `stdin` pipe:

```python
process = await asyncio.create_subprocess_exec(
    *cmd,
    stdin=asyncio.subprocess.PIPE,
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    env=sanitized_env,
    cwd=runtime_dir
)

# Asynchronous write and atomic pipe closure to transmit EOF
if process.stdin:
    prompt_bytes = (job.prompt or "").encode('utf-8')
    process.stdin.write(prompt_bytes)
    await process.stdin.drain()
    process.stdin.close()
    await process.stdin.wait_closed()
```

### UTF-8 Decoding and OS Pipe Deadlock Prevention
To prevent subprocess hangs caused by operating system pipe buffer saturation (OS Pipe Deadlock), `stdin`, `stdout`, and `stderr` pipes are processed concurrently via `asyncio.gather()`:

1. **`stdout` Reading and SSE Streaming**:
   Tokens emitted by the core are decoded incrementally in 1024-byte chunks using an incremental UTF-8 decoder (`codecs.getincrementaldecoder('utf-8')(errors='replace')`), buffered into the Job's RAM memory, and immediately dispatched to the client's SSE queue:
   ```text
   id: 1
   event: token
   data: {"delta": "Hello"}

   id: 2
   event: token
   data: {"delta": "!"}
   ```

2. **`stderr` Reading and Diagnostic Parsing (Zero Regex)**:
   Error diagnostics rely on parsing valid JSON lines emitted by `bash4llm` (`emit_json_diagnostics`), capturing `code`, `message`, and `reason` (e.g., error code 10 automatically mapped to *"Vault is locked or API key missing"*):
   ```json
   {"bash4llm_status":"ERROR","code":10,"reason":"NO_API_KEY","message":"GROQ_API_KEY is not set","timestamp":"2026-08-10T17:00:00Z"}
   ```

### 2-Tier NDJSON Resolution (`GET /api/threads/{id}`)
To serve conversation message history without subprocess overhead, the Adapter performs a **Read-Only** scan:

1. **Syntax Validation**: Validates the conversation ID format via regex `^[A-Za-z0-9._-]{1,128}$`.
2. **Canonical Directory Scan**: Searches concurrently across `history/sessions/` and `history/threads/`.
3. **File Resolution**: Looks for both the SHA-256 digest (`{sha256_hex}.ndjson`) and plaintext ID (`{thread_id}.ndjson`), including segmented files (`{id}.*.ndjson`).
4. If no matching files exist, the Adapter returns an empty array `[]`.

## 5. Security Model and Route Protection

### Tree-Structured Security Architecture

```text
[HTTP Request GET / or POST /api/chat]
        │
        ├── 1. Host Validation (Allowlist: 127.0.0.1, localhost, [::1])
        │
        ├── 2. Primary Origin Validation (Origin must match http://127.0.0.1:PORT)
        │
        ├── 3. Session Cookie Check (HttpOnly Cookie: session_id)
        │        │
        │        ├── Missing/Invalid on GET / or GET /index.html ──> Return HTTP 401 (error.html)
        │        └── Missing/Invalid on Mutating APIs ──────────> Return HTTP 401 (JSON)
        │
        ├── 4. Anti-CSRF Token Header Check (X-CSRF-Token for POST, PUT, PATCH, DELETE)
        │
        ├── 5. Job Ownership Check (Ownership bound to owner_session_id)
        │
        └── 6. Fingerprinted Ephemeral Idempotency Check (SHA-256 Payload Fingerprint)
                 ├── Preexisting Key + Same SHA-256 Fingerprint ──> Return 202 Accepted (Existing Job)
                 ├── Preexisting Key + DIFFERENT Fingerprint ─────> Return HTTP 409 Conflict
                 └── New Key ─────────────────────────────────────> Allocate and execute new Job
```

### Specific Protection Mechanisms

* **Strict Tempdir Validation (T3 Hardened)**: The `validate_runtime_tmpdir` function explicitly rejects shared system paths (`/tmp`, `/var/tmp`, `/private/tmp`, `/private/var/tmp`, `c:\windows\temp`), enforces directory creation with `0700` permissions, and verifies that owner UID strictly matches the current executing user (`os.geteuid()`).
* **Exclusive Loopback Binding**: The Uvicorn server binds strictly to local loopback addresses (`127.0.0.1` or `[::1]`). Binding to `0.0.0.0` is strictly prohibited.
* **Single-Instance Advisory Lock**:
  * **POSIX**: `fcntl.flock(fd, fcntl.LOCK_EX | fcntl.LOCK_NB)` on the `gui_adapter.lock` file with `0600` permissions.
  * **Windows**: `msvcrt.locking(fd, msvcrt.LK_NBLCK, 1)` following a 1-byte initialization write.
  * The OS kernel automatically releases the lock upon process termination or crash, eliminating the risk of stale lock files.
* **Cookies & Anti-CSRF**:
  * Session cookie: `Set-Cookie: session_id=...; HttpOnly; SameSite=Strict; Path=/`.
  * CSRF Token: Generated in RAM (`secrets.token_hex(32)`), returned in the `/api/status` payload, and validated in constant time (`secrets.compare_digest`) on the `X-CSRF-Token` header for all mutating operations (`POST`, `PUT`, `PATCH`, `DELETE`).
* **One-Time Bootstrap Token (Direct Handshake)**:
  * At startup, `active_one_time_token = secrets.token_hex(32)` is generated.
  * The endpoint `/auth?one_time_token=XYZ` validates the token, consumes it atomically in RAM (`active_one_time_token = None`), assigns the session cookie, and directly returns `index.html` with status `200 OK`, eliminating any cookie-drop risks associated with browser redirects.

### Semantics of `HTTP 202 Accepted` Status
The `HTTP 202 Accepted` response returned by the `POST /api/chat` endpoint indicates that the request was syntactically validated and the `Job` object has been **allocated in the Adapter runtime**. Any execution errors from the Bash script or remote API (error codes $10\div17$) are conveyed asynchronously within the SSE stream (`event: done`) and in the Job object queryable via `GET /api/jobs/{id}`.

## 7. Cross-Platform Compatibility Matrix & Resilience

### Portability Matrix

| Target Platform | Core Bash Requirement | Python Engine | OS Lock & Tree Termination Method | Engineering Notes & Dependencies |
| :--- | :--- | :--- | :--- | :--- |
| **Linux (Generic)** | Bash >= 4.0 | Python 3.10+ | `fcntl.flock` \| `os.kill(pid, SIGTERM)` | Full native support. UID validation and `0700` permissions on `BASH4LLM_TMPDIR`. |
| **macOS (Darwin)** | Bash >= 4.0 | Python 3.10+ | `fcntl.flock` \| `os.kill(pid, SIGTERM)` | Native BSD utilities. Zero dependencies on non-standard external binaries. |
| **WSL (Microsoft)** | Bash >= 4.0 | Python 3.10+ | `fcntl.flock` \| `os.kill(pid, SIGTERM)` | Equivalent behavior to native Linux. Interop launcher with `wslview`/PowerShell. |
| **Android (Termux)** | Termux Bash (4.0+) | Python 3.10+ | `fcntl.flock` \| `os.kill(pid, SIGTERM)` | Browser launch with `termux-open-url`. URL printed to console. JS auto-reconnect on Doze Mode. |
| **Windows (Git Bash / MSYS2)**| Bash >= 4.0 (Git Bash) | Python Windows | `msvcrt.locking` \| `taskkill /F /T /PID` | 1-byte lock file initialization. Windows path normalization. |

### Mobile Resilience & Termux (Android Doze Mode)

On mobile devices running Android/Termux, power-saving mechanisms (*Doze Mode*) or aggressive OS policies can temporarily suspend the browser process or terminate the SSE socket TCP connection.

To ensure maximum resilience:
1. **Independent Asynchronous Pipelining**: The Bash subprocess continues execution and response persistence to NDJSON files even if the web client disconnects from the SSE stream.
2. **Auto-Reconnect EventSource**: The Vanilla JavaScript client (`app.js`) handles `eventSource.onerror`, attempting automatic reconnection to `/api/stream/{job_id}`.
3. **SSE Heartbeat Keepalive**: The asynchronous generator of the `/api/stream/{job_id}` endpoint sends a keepalive comment (`: heartbeat\n\n`) every 15 seconds of inactivity to prevent socket closure by network middleboxes.
